# 下一版：加强高度惩罚与站立承重分配

## 已完成的配置修改

在 `lz_q1l_2_config.py` 追加 `LZQ1LFlatV2GaitHeightCfg` / PPO，注册任务
`lz_q1l_flat_v2_gait_height`，环境扩展为 `LZQ1LV2GaitHeightRobot`。
高度配置差异为 `rewards.scales.base_height: -10 -> -30`；另有下述站立承重项。
目标仍为机身参考点离平地0.30 m，不是头顶高度。
现有函数是高度误差平方，因此高于目标也会受罚；这是增强高度跟踪，
不是把目标高度提高，也不是新加一个单侧奖励。

公式（基础代码统一乘dt前）：`-30*(height-0.30)^2`。
低于目标2 cm时，代价从0.004增至0.012；低5 cm时从0.025增至0.075。
这是初始候选权重，尚无新训练结果；修改配置不会改变已训练模型的动作。
旧gait200配置和模型保留。随后用户已授权在该model_200基础上新增训练300轮，
每50轮保存，继承完整网络、两个优化器状态及PPO学习率。
本阶段保存编号50/100/150/200/250/300，旧检查点不覆盖。
启动入口 `tools/start_lz_q1l_v2_gait_height_300.sh`，状态指针
`media/v2_gait_height_20261025/latest_training.json`。质量指标仅记录，不提前停训。

## 已按用户授权实现的站立承重约束

证据：`media/gait200_analysis_20261025/analysis.json`。新模型站立配对复测
左后/右后平均约72.1/14.0 N，左前/右前约21.4/42.2 N，四脚均接触。
此前新增三项仅在直行启用，站立支撑项只约束离地，不约束承重分工。

新增仅站立启用的 `stand_pair_force_balance`，初始权重-0.5：

- 零指令判定沿用现有每轴绝对值不超过0.05的条件；切入站立后等待0.5 s。
- 对各脚正向Fz做0.5 s滑动平均；切换指令、重置时清空历史；窗口完整后计罚。
- 前腿和后腿分别计算 `b=abs(L-R)/(L+R+1N)`。
- 代价为前后两组 `max(b-0.10,0)^2` 的均值；不强制前后重量相等。
- 保留原站立离地惩罚，并给每脚增加低承重保护：若某脚平均力低于四脚
  总平均力的10%，罚归一化短缺平方的四脚均值；独立项 `stand_low_load` 初始
  权重-0.2，避免只靠两只脚支撑却左右平衡的漏洞。保留原有站立离地项。
- 行走保留当前1 s后腿平均力平衡项，暂不提高其权重；不按瞬时左右相等计罚。

仅左右总力相等无法排除对角偏重；仅后腿平衡又可能把不平衡转移到前腿。
分别约束前后左右对，允许合理前后配重。10%为归一化差值容差，不是每脚
必须占总重量25%。窗口和权重均是候选值，非已验证最优参数。

低承重项：`s_i=F_i/max(sum(F),1e-6 N)`，代价为
`mean(clamp((0.10-s_i)/0.10,0,1)^2)`。F为0.5秒平均正向支撑力。
全部零支撑时该项为1，避免零除和“完全不承重但平衡”的漏洞。
力的滑动窗口每个控制步只更新一次；奖励函数只读取缓存。
缓冲与完整窗口同时计时，0.5秒后开始计算，并非叠加等待1秒。
