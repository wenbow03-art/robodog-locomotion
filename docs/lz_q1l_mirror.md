# LZ-Q1L 镜像推理对照

镜像包装器位于 `HIMLoco/legged_gym/legged_gym/utils/lz_q1l_mirror.py`。
它镜像六帧观测，调用原估计器和 actor，再镜像输出动作；不修改权重。
关节映射按仿真返回的名称建立，左右腿交换，roll 变号，两个 pitch 保持符号。
命令符号为 `[+, -, -]`，角速度为 `[-, +, -]`，重力投影为 `[+, -, +]`。
估计速度只在报告时变回实际机身坐标；16 维 latent 不手工变换。

## 使用

**LZ-Q1L 普通仿真和录制现在统一自动使用组合策略，无需任何镜像参数。**
纯左移使用镜像策略；右移、站立、前进、转向及斜向运动使用原策略。
统一入口为 `HIMOnPolicyRunner.get_inference_policy()`，它调用
`LZQ1LRobot.build_inference_policy()`。`play.py`、`tools/record_lz_q1l.py`
以及使用这个 runner 的已有视频录制脚本都会自动获得组合策略。
其他机器人任务不受影响。回放时只需像平时一样指定模型和运动指令，例如：

```text
--command 0 0.4 0
```

`--command` 顺序为 vx、vy、yaw rate。组合模式按最新一帧的实际命令选择，
反归一化后 vy > 1e-6、abs(vx) <= 1e-6、abs(yaw rate) <= 1e-6 才镜像。
整段六帧历史按当前分支转换，不改写物理历史，也不在切换时清空历史。

全局镜像策略类及 `--mirror-policy`、`--policy-mode` 选择参数均已删除。
以后无需选择模式；新录制入口同样通过 runner 获取策略，不直接调用裸 actor。
项目根目录 `AGENTS.md` 已记录这一用户要求，供后续仿真/录制任务遵循。
组合回放跳过原来的 JIT 导出；训练网络、checkpoint 权重和真实机器人部署
程序没有改变。明确标注的原始模型对照/估计器消融仍可直接使用裸 actor。
历史视频、结果和代码快照保留；旧录制启动器的哈希锁定记录不用于新实验。

在项目根目录重跑批量对照：

```bash
bash tools/run_lz_q1l_mirror.sh --transitions
```

启动器使用已有 `.env` 和 GPU 2，检查显存低于 500 MiB 后才启动。
每次创建独立结果目录，保存代码快照、哈希、逐步轨迹和汇总。

统一入口验证目录：`media/lz_q1l_mirror/eval_20261023_214459_BiKb/`。
本轮通过实际 `HIMOnPolicyRunner` 构造并加载原 V8，调用无镜像参数的
`get_inference_policy()` 自动得到组合策略，6 项代码测试通过。
两随机种子、11 项持续指令、每项 32 次中，组合策略结果与上一轮显式组合
控制器完全一致；原策略对照的站立项有微小数值差异，其余一致。
代码快照和 checkpoint 哈希核验通过。入口调整没有改变切换算法，
此前的方向切换限制仍适用。

## 组合模式验证（2026-10-23）

结果目录：`media/lz_q1l_mirror/eval_20261023_213453_0LeI/`。
六项 CPU 检查通过，包括混合命令批次、当前帧路由、历史保持及两条分支的
动作/估计速度等价性。GPU 仿真完成，原 checkpoint 哈希未变化。

持续命令测试每项 32 次、每次 12 秒，速度统计排除前 2 秒和首次终止后数据。

| 命令 | 组合策略实际速度 (m/s) | 失败次数 |
|---|---:|---:|
| 左移 +0.4 | +0.4624 | 3/32 |
| 右移 −0.4 | −0.4487 | 1/32 |
| 左移 +0.2 | +0.1463 | 0/32 |
| 右移 −0.2 | −0.0984 | 1/32 |
| 前进 +0.5 | +0.5267 | 10/32 |

右移/前进路径使用原 actor/估计器，不代表独立仿真环境中的轨迹逐步相同；
PhysX 接触和浮点数值可能造成差异。不能将右移失败数变化解读成原分支被优化。

另外测试了 14 秒指令序列，每项 32 次，原/组合策略初始根速度配对；
不同序列的起始状态并未配对。全程第一次失败计数如下：

| 指令序列 | 组合模式全程失败 | 目标切换后对应运动段新增失败 |
|---|---:|---:|
| 站立→左移→停 2 秒→右移→站立 | 1/32 | 右移段 0；唯一失败发生在左移段 |
| 站立→左移→直接右移→站立 | 5/32 | 右移段 1；其余 4 次发生在此前左移段 |
| 站立→右移→直接左移→站立 | 5/32 | 左移段 2；此前右移段 3 |
| 站立→左移→停 2 秒→前进→站立 | 9/32 | 前进段 7；此前左移 1，最后站立 1 |

这些是全序列失败数，不能都归因于模式切换，也不能以不同序列的总失败数
证明停顿的因果收益。分段速度、姿态和切换瞬间最大关节目标变化在
`switches_seed1.json` / `switches_seed2.json` 中，逐步轨迹在同名 NPZ 中。
当前按命令立即选择分支，**没有自动插入停顿或平滑混合**。组合模式保留了两边
持续侧移能力，但仍有失败，不能视为稳定性问题全部解决。
